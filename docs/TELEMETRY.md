# Формат телеметрии

Один JSON-объект на строку, окончание LF (`\n`). Панель также принимает CRLF/CR, префиксы ESP-IDF и исходный многострочный формат EKF/ACC/GYRO/MAG/BIAS. Строки загрузки и калибровки не считаются измерениями.

## По умолчанию: датчики → AHRS браузера

```json
{"v":1,"t_us":1000000,"seq":1,"ax":0.1911,"ay":-0.1360,"az":0.9778,"gx":0.183,"gy":-0.183,"gz":-0.183,"mx":-11,"my":39,"mz":32,"mag_frame":"bmi270","mag_age_ms":20}
```

| Поля | Значение | Единицы |
|---|---|---|
| `ax,ay,az` | Акселерометр BMI270 | g |
| `gx,gy,gz` | Гироскоп BMI270 | °/с |
| `mx,my,mz` | Компенсированный BMM150, после настроек MAG | µT |
| `mag_frame` | Система MAG: `bmi270` — уже совмещён, `bmm150` — собственные оси магнитометра | строка |
| `t_us` | Время завершения чтения IMU на ESP32 | мкс от запуска |
| `seq` | Счётчик отправленных пакетов | 0, 1, 2… |
| `mag_age_ms` | Время после последнего успешного API-чтения MAG | мс |
| `acc_used`, `mag_used` | Диагностические статусы MEKF прошивки; браузер имеет собственные статусы коррекции | true/false |

Старый поток только из девяти полей `ax…mz` тоже работает. При отсутствии `t_us` панель использует приблизительные интервалы приёма USB. `t_us` не является аппаратным timestamp BMI270; возраст MAG не доказывает свежесть физической выборки.

Без `mag_frame` по умолчанию используется монтаж по фото: MAG преобразуется `(-X,+Y,-Z)` **до AHRS**. Для старой прошивки с уже совмещённым MAG выберите в панели «MAG без отметки осей → Уже в осях IMU». Новая прошивка преобразует MAG до MEKF и помечает `mag_frame=bmi270`, что исключает повторный поворот в браузере. Неизвестное значение поля исключает MAG из расчёта. Исходный пакет остаётся неизменным.

Ориентацию оценивает комплементарный AHRS в JavaScript в собственных осях BMI270: гироскоп предсказывает вращение, ACC корректирует наклон, MAG — курс. Это отдельный алгоритм, а не MEKF в ESP32. После фильтра панель применяет общую поправку монтажа к ориентации и измерениям для отображения, графиков и CSV. В журнале без timestamp гироскоп не интегрируется; временная шкала графиков условная, 100 мс на строку.

## Дополнительно: MEKF прошивки → панель

Выберите `QAV250 → Serial telemetry format → Firmware MEKF JSON` в `idf.py menuconfig`, затем пересоберите и прошейте устройство.

```json
{"v":1,"t_us":1000000,"seq":1,"q":[1,0,0,0],"a_g":[0,0,1],"g_dps":[0,0,0],"m_uT":[23,0,-40],"mag_frame":"bmi270","bias_dps":[0,0,0],"dt_s":0.01,"acc_used":true,"mag_used":true,"mag_age_ms":20}
```

`q=[w,x,y,z]` описывает IMU → мир (body прошивки — оси BMI270). Панель нормализует q и применяет поправку монтажа перед использованием для модели, углов и матрицы. По умолчанию действует номинальный профиль корпуса по фото, сохранённая калибровка имеет приоритет. «Сбросить монтаж» включает тождественное преобразование. `dt_s` — внутренний шаг фильтра, а не интервал между отправленными JSON-пакетами. Статусы `acc_used`/`mag_used` относятся к коррекциям MEKF. В режиме браузера его собственные статусы показаны отдельно. Если старый q/RPY вычислен с несовмещённым MAG, нужна обновлённая прошивка; браузер предупреждает об этом и не выдаёт преобразование выходного q за исправление MEKF.

Также распознаются `quaternion`, `{w,x,y,z}`, `qw,qx,qy,qz`, `rpy_deg`, `rpy_rad` и отдельные `roll_deg,pitch_deg,yaw_deg`. Для полей без суффикса единицы не угадываются. Недоступные измерения остаются пустыми; они не заменяются демоданными.

## Барометр: дополнительные поля в обоих режимах

| Поле | Значение | Единицы |
|---|---|---|
| `pressure_pa` | Компенсированное давление BMP388/BMP390; при недостоверности `null` | Pa |
| `temperature_c` | Температура кристалла; при недостоверности `null` | °C |
| `baro_valid` | Есть корректное измерение не старше 500 мс | true/false |
| `baro_age_ms` | От начала последнего успешного чтения BMP3xx до формирования JSON; до первого чтения `null` | мс |
| `baro_model` | `BMP388`, `BMP390` или `null` при отсутствии инициализации | строка |
| `baro_address` | 118 (0x76), 119 (0x77) или `null` | 7-битный адрес |

Эти поля добавляются в тот же JSON-объект с IMU; версия формата остаётся 1. Старый поток без них по-прежнему принимается. Пример:

```json
{"v":1,"t_us":1000000,"seq":1,"ax":0,"ay":0,"az":1,"gx":0,"gy":0,"gz":0,"mx":25,"my":0,"mz":-40,"mag_frame":"bmi270","pressure_pa":100025,"temperature_c":25,"baro_valid":true,"baro_age_ms":2,"baro_model":"BMP390","baro_address":119}
```

Панель делит давление на 100 для графика hPa, но экспортирует Pa. CSV добавляет все шесть полей барометра, пустые ячейки означают отсутствие значения. Ошибочное давление/температура не отбрасывают корректную ориентацию. Явный false, некорректные метаданные свежести или возраст более 500 мс исключают барометр из графиков. В режиме USB текущий readout также скрывается при устаревании с учётом времени приёма либо отключении порта; пауза и журнал показывают сохранённый кадр с соответствующей пометкой. Исторический график не стирается при отключении.

Опрос BMP3xx идёт примерно на 10 Гц, при готовности обоих каналов. Это отдельные скаляры, не вход MEKF/AHRS и не векторы для преобразования IMU → корпус. Ни высота, ни вертикальная скорость здесь не вычисляются. Подробности: [BAROMETER.md](BAROMETER.md).

## Координаты и ограничения

Профиль «По фото · вперёд к USB» задаёт `X_body = −Y_IMU, Y_body = X_IMU, Z_body = Z_IMU`. Это начальная оценка монтажа по стрелкам, точный перекос уточняется двумя шагами «Плата лежит ровно» и «Передняя сторона вниз». При сбросе монтажа панель подписывает систему как IMU и использует собственные X/Y/Z входной телеметрии. Корпус имеет X вперёд, Y влево, Z вверх: положительный Pitch опускает нос, Roll — правый бок, Yaw поворачивает нос влево. Общая поправка корпуса не измеряет независимый перекос BMM150 относительно BMI270. Направления, выводы по фото и проверка описаны в [HARDWARE_PHOTO.md](HARDWARE_PHOTO.md).

Обозначения: S — IMU, B — корпус, W — мир фильтра, D — мир панели с выбранным нулём курса. `R_BS` переводит вектор из S в B. При нормализованных измерениях ACC в горизонтальном положении `a0` и с носом вниз `a1`:

```text
z_S = unit(a0)
x_S = unit(dot(unit(a1), z_S) * z_S - unit(a1))
y_S = unit(cross(z_S, x_S))
R_BS = [x_S; y_S; z_S]          // оси корпуса в координатах IMU, строки
v_B = R_BS * v_S                 // ACC, GYRO, MAG и bias
q_DB = q_DW * q_WS * inverse(q_BS)
R_DB = R(q_DB)
```

`q_DW` вращает только вокруг мировой вертикали для нуля курса. После калибровки ноль берётся из сохранённого горизонтального положения, при новом подключении — из первой доступной ориентации корпуса. «Обнулить курс» меняет только `q_DW`, не перезапускает AHRS и не вычитает углы Эйлера. Поэтому компенсация перекоса около 10° остаётся правильной и при совместных вращениях. В интерфейсе матрица обозначена `R`, направление показано формулой `v_world = R · v_body` (при сбросе монтажа — `v_IMU`).

Оба положения калибровки усредняются за последний примерно секундный интервал: минимум 8 пакетов, длительность минимум 0,7 с, ACC 0,9–1,1 g, разброс направления не более 2°, нормы — не более 0,04 g, скорость GYRO с вычетом доступного bias — не более 5 °/с. Наклон между положениями должен быть 15–60°. Демонстрационные, устаревшие и движущиеся данные не принимаются. По двум статическим положениям определяется установка IMU, но не смещение нуля самого акселерометра.

Монтаж сохраняется в `localStorage` (`qav250.imu-mount.v1`) для одного браузера и адреса панели. Поле `source` отличает `native`, `photo_usb`, `calibrated`; старые сохранённые калибровки без source по-прежнему работают. Настройка MAG без отметки осей сохраняется отдельно (`qav250.legacy-mag-axes.v1`). На странице действует один профиль; для другой платы или журнала другой установки его нужно сбросить или откалибровать заново. При изменении монтажа или нуля курса накопленная история пересчитывается из сохранённых данных в осях IMU, без повторного применения фильтра. Изменение настройки MAG перезапускает AHRS: для журнала исходные пакеты обрабатываются заново, для USB ожидается новый поток. Исходные строки Serial не изменяются. В CSV записываются `coordinate_frame` (`imu_native`, `body_photo`, `body_calibrated`, `demo`), `mount_qw…mount_qz` (S → B), `heading_zero_deg`, `mag_input_frame` и `mag_mapping` (`identity`, `photo_y180`, `unavailable`).

Одна матрица R поворачивает корпус, моторы и указатель осей. Положение, высота и обороты моторов не измеряются. В режиме USB пропеллеры не вращаются, поскольку RPM отсутствует.

`MAG_OFFSET_*` и `MAG_SCALE_*` в `main.c` — исходные заглушки. Для точного курса нужны калибровка магнитометра и проверка осей. Ноль курса привязан к старту, не к географическому северу. Ограничения исходного MEKF описаны в [разборе](QAV250_EKF_review.md).
