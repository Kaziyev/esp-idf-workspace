# Формат телеметрии

Один JSON-объект на строку, окончание LF (`\n`). Панель также принимает CRLF/CR, префиксы ESP-IDF и исходный многострочный формат EKF/ACC/GYRO/MAG/BIAS. Строки загрузки и калибровки не считаются измерениями.

## По умолчанию: датчики → AHRS браузера

```json
{"v":1,"t_us":1000000,"seq":1,"ax":0.1911,"ay":-0.1360,"az":0.9778,"gx":0.183,"gy":-0.183,"gz":-0.183,"mx":-11,"my":39,"mz":32,"mag_age_ms":20}
```

| Поля | Значение | Единицы |
|---|---|---|
| `ax,ay,az` | Акселерометр BMI270 | g |
| `gx,gy,gz` | Гироскоп BMI270 | °/с |
| `mx,my,mz` | Компенсированный BMM150, после настроек MAG | µT |
| `t_us` | Время завершения чтения IMU на ESP32 | мкс от запуска |
| `seq` | Счётчик отправленных пакетов | 0, 1, 2… |
| `mag_age_ms` | Время после последнего успешного API-чтения MAG | мс |
| `acc_used`, `mag_used` | Диагностические статусы MEKF прошивки; браузер имеет собственные статусы коррекции | true/false |

Старый поток только из девяти полей `ax…mz` тоже работает. При отсутствии `t_us` панель использует приблизительные интервалы приёма USB. `t_us` не является аппаратным timestamp BMI270; возраст MAG не доказывает свежесть физической выборки.

Ориентацию оценивает комплементарный AHRS в JavaScript в собственных осях BMI270: гироскоп предсказывает вращение, ACC корректирует наклон, MAG — курс. Это отдельный алгоритм, а не MEKF в ESP32. После фильтра панель применяет общую поправку монтажа к ориентации и измерениям для отображения, графиков и CSV. В журнале без timestamp гироскоп не интегрируется; временная шкала графиков условная, 100 мс на строку.

## Дополнительно: MEKF прошивки → панель

Выберите `QAV250 → Serial telemetry format → Firmware MEKF JSON` в `idf.py menuconfig`, затем пересоберите и прошейте устройство.

```json
{"v":1,"t_us":1000000,"seq":1,"q":[1,0,0,0],"a_g":[0,0,1],"g_dps":[0,0,0],"m_uT":[23,0,-40],"bias_dps":[0,0,0],"dt_s":0.01,"acc_used":true,"mag_used":true,"mag_age_ms":20}
```

`q=[w,x,y,z]` описывает IMU → мир (body прошивки — оси BMI270). Панель нормализует q и применяет поправку монтажа перед использованием для модели, углов и матрицы. Без калибровки преобразование монтажа тождественное. `dt_s` — внутренний шаг фильтра, а не интервал между отправленными JSON-пакетами. Статусы `acc_used`/`mag_used` относятся к коррекциям MEKF. В режиме браузера его собственные статусы показаны отдельно.

Также распознаются `quaternion`, `{w,x,y,z}`, `qw,qx,qy,qz`, `rpy_deg`, `rpy_rad` и отдельные `roll_deg,pitch_deg,yaw_deg`. Для полей без суффикса единицы не угадываются. Недоступные измерения остаются пустыми; они не заменяются демоданными.

## Координаты и ограничения

До калибровки панель подписывает систему как IMU: её X/Y/Z совпадают с осями входной телеметрии. После двух шагов «Плата лежит ровно» и «Передняя сторона вниз» система корпуса становится X вперёд, Y влево, Z вверх. Это правая система: положительный Pitch опускает нос, Roll — правый бок, Yaw поворачивает нос влево. `remap_mag_axes()` должен заранее переводить BMM150 в оси BMI270; общая поправка монтажа не определяет независимую ориентацию магнитометра.

Обозначения: S — IMU, B — корпус, W — мир фильтра, D — мир панели с выбранным нулём курса. `R_BS` переводит вектор из S в B. При нормализованных измерениях ACC в горизонтальном положении `a0` и с носом вниз `a1`:

```text
z_S = unit(a0)
x_S = unit(dot(unit(a1), z_S) * z_S - unit(a1))
y_S = unit(cross(z_S, x_S))
R_BS = [x_S; y_S; z_S]          // оси корпуса в координатах IMU, строки
v_B = R_BS * v_S                 // ACC, GYRO, MAG и bias
q_DB = q_DW * q_WS * inverse(q_BS)
R_DB = R(q_DB)
```

`q_DW` вращает только вокруг мировой вертикали для нуля курса. После калибровки ноль берётся из сохранённого горизонтального положения, при новом подключении — из первой доступной ориентации корпуса. «Обнулить курс» меняет только `q_DW`, не перезапускает AHRS и не вычитает углы Эйлера. Поэтому компенсация перекоса около 10° остаётся правильной и при совместных вращениях. В интерфейсе матрица обозначена `R`, направление показано формулой `v_world = R · v_body` (до калибровки — `v_IMU`).

Оба положения калибровки усредняются за последний примерно секундный интервал: минимум 8 пакетов, длительность минимум 0,7 с, ACC 0,9–1,1 g, разброс направления не более 2°, нормы — не более 0,04 g, скорость GYRO с вычетом доступного bias — не более 5 °/с. Наклон между положениями должен быть 15–60°. Демонстрационные, устаревшие и движущиеся данные не принимаются. По двум статическим положениям определяется установка IMU, но не смещение нуля самого акселерометра.

Монтаж сохраняется в `localStorage` (`qav250.imu-mount.v1`) для одного браузера и адреса панели. На странице действует один профиль; для другой платы или журнала другой установки его нужно сбросить или откалибровать заново. При изменении монтажа или нуля курса накопленная история пересчитывается из сохранённых данных в осях IMU, без повторного применения фильтра. Исходные строки Serial не изменяются. В CSV дополнительно записываются `coordinate_frame` (`imu_native`, `body_calibrated`, `demo`), `mount_qw…mount_qz` (S → B) и `heading_zero_deg`. Эти поля позволяют восстановить выбранные преобразования.

Одна матрица R поворачивает корпус, моторы и указатель осей. Положение, высота и обороты моторов не измеряются. В режиме USB пропеллеры не вращаются, поскольку RPM отсутствует.

`MAG_OFFSET_*` и `MAG_SCALE_*` в `main.c` — исходные заглушки. Для точного курса нужны калибровка магнитометра и проверка осей. Ноль курса привязан к старту, не к географическому северу. Ограничения исходного MEKF описаны в [разборе](QAV250_EKF_review.md).
