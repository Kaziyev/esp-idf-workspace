# Проверка комплекта

## BMP3xx — 20 сентября 2026

После добавления барометра выполнены:

- `node --check web/app.js` и `node tests/telemetry.cjs` — успешно. Для этого запуска использованы 120 синтетических кадров, не новые аппаратные измерения. Проверены raw/MEKF, Pa → hPa, °C, некорректные/пропущенные поля, возраст 500 мс, отключение USB, пауза, журнал, оба набора графиков, CSV и независимость скаляров от калибровки осей.
- C-тест `tests/barometer.c`, собранный вместе с **настоящими** `bmp3.c` и `barometer.c` через GCC с `-Wall -Wextra -Werror`, — успешно. Имитация I²C содержит синтетические регистры и коэффициенты: проверяются оба chip ID, запись ODR/OSR/IIR/normal mode, компенсация в Pa/°C, оба DRDY, отсутствие ожидания конверсии, ошибки шины/инициализации, предупреждения диапазона и JSON с `null`.
- `node tests/telemetry.cjs --barometer-exe ./build-tests/barometer.exe` — успешно: JSON, сформированный C-адаптером, проходит через нормализацию панели, включая отсутствие барометра.
- Полные сборки **ESP32-S3 на установленном ESP-IDF v6.0.1 / Xtensa GCC 15.2.0**: raw — `0x36aa0` байт, MEKF — `0x36cc0` байт, обе помещаются в раздел 1 МиБ. Использованы отдельные конфигурации во временной копии с латинским путём: GCC v6-toolchain не смог прочитать specs-файл из исходного пути с кириллицей. В обоих режимах осталась прежняя warning об unused `quat_to_euler`; новых ошибок нет.
- `sdkconfig` и базовая версия проекта v5.4.1 не изменялись. Сборка новой версии именно на v5.4.1 **не выполнялась**. Проверка на v6.0.1 подтверждает компиляцию, но не является миграцией UART/USB-настроек или рекомендацией прошить проверочный бинарник без проверки конфигурации своей платы.
- Панель открыта в браузере на localhost: обе новые линии и единицы видны, синтетические данные явно помечены «ДЕМО», ошибок JavaScript в консоли не обнаружено. Реальный USB-порт не открывался.

Воспроизведение host-тестов в PowerShell из корня репозитория (нужны GCC и Node.js):

```powershell
New-Item -ItemType Directory -Path build-tests -Force | Out-Null
gcc -std=c11 -Wall -Wextra -Werror tests/barometer.c apps/i2c_imu/main/barometer.c apps/i2c_imu/main/bmp3.c -lm -o build-tests/barometer.exe
./build-tests/barometer.exe
node tests/telemetry.cjs --barometer-exe ./build-tests/barometer.exe
```

Плата не прошивалась; работоспособность нового датчика, точность давления и влияние общей шины на реальную частоту IMU требуют аппаратной проверки по [BAROMETER.md](BAROMETER.md).

## Предыдущие проверки

Проверено 16 сентября 2026 года. Полные сборки выполнены для ESP32-S3; физическая плата в этой среде недоступна, прошивка и работа датчиков на устройстве здесь не проверялись.

## Прошивка

Окружение: ESP-IDF **v5.4.1**, commit `4c2820d377d1375e787bcef612f0c32c1427d183`, Xtensa GCC **14.2.0**, CMake **3.30.5**, Ninja **1.11.1.1**, Python **3.12.14**.

| Конфигурация | Результат | Размер приложения |
|---|---|---|
| `CONFIG_QAV250_OUTPUT_RAW_JSON=y` — по умолчанию | Полная сборка успешна | `0x3ed40` байт |
| `CONFIG_QAV250_OUTPUT_EKF_JSON=y` | Полная сборка успешна | `0x3ef40` байт |

Обе сборки помещаются в раздел приложения `0x100000` байт; свободно около 75%. Использованы драйверы Bosch из этого репозитория и стек основной задачи 8192 байт. Компилятор сообщает о неиспользуемой исходной функции `quat_to_euler`; ошибок компиляции и линковки нет. Размеры могут измениться при другой конфигурации или версии инструментов.

В проверочной среде был установлен `IDF_COMPONENT_MANAGER=0`: определение процессов внутри контейнера вызывало ошибку вспомогательного менеджера. Внешних управляемых компонентов у проекта нет; все требуемые драйверы включены в исходники. Это настройка окружения сборки, а не изменение прошивки. Обычная инструкция запуска — в [README](../README.md).

## Панель

20 сентября 2026: для профиля по фотографии прошли `node tests/telemetry.cjs` и отдельный C-тест `tests/sensor_axes.c`, собранный системным GCC с `-Wall -Wextra -Werror`. Проверены направление вперёд к USB, преобразование BMM150 `(-X,+Y,-Z)` до AHRS, траектории по трём осям через старый raw и новый MEKF JSON, отметка `mag_frame` и отсутствие двойного поворота, сохранение/сброс профилей. Полная сборка новой версии под ESP-IDF v5.4.1 в этой проверке не выполнялась: локально обнаружена v6.0.1. Результаты сборок прошивки выше относятся к версии от 16 сентября. Фото задаёт номинальные направления, не точные монтажные углы и не магнитную калибровку.

Дополнительно для калибровки монтажа: проверены семь синтетических установок IMU, включая поворот на ±90°, перекос на 10°, совместные вращения и перевёрнутый датчик. Проверены знаки всех трёх осей, матрица с det = +1, преобразование ACC/GYRO/MAG/bias, оба источника ориентации (raw AHRS и firmware q), двухшаговая калибровка, сохранение профиля, обнуление курса без изменения наклонов, пересчёт истории, CSV, отбрасывание движения и устаревших данных. Физическое соответствие направлению «вперёд» задаёт пользователь при выполнении двух шагов на своей плате.

- `node --check web/app.js` — синтаксис корректен.
- `node tests/telemetry.cjs` — проверки проходят: raw/q/RPY, наклон и курс, интегрирование гироскопа, единицы измерений, разрывы времени, дробление Serial-потока, передача данных в модель, матрицу и графики, пауза и CSV.
- Дополнительно разобраны **120 реальных JSON-строк** из предоставленной диагностики: **120 приняты, 0 отклонены**. Файл диагностики не включён в публичный комплект. Свой файл можно проверить командой `node tests/telemetry.cjs path/to/diagnostic.txt`.
- Локальный Python-сервер отдаёт HTML, CSS и JavaScript с HTTP 200 и соответствующими типами содержимого; файлы за пределами `web` не публикуются.
- Проверены ссылки HTML на локальные CSS/JS и уникальность идентификаторов элементов.

Проверки JavaScript используют имитацию браузера и Serial-транспорта. Они подтверждают обработку пакетов, но не заменяют подключение настоящего COM-порта в Chrome/Edge. Отдельный запуск Windows `.bat` на Windows в этой среде не выполнялся.

## Что требует проверки на сборке друга

Выводы I2C и канал USB-консоли должны соответствовать плате; оси датчиков и калибровка MAG — монтажу. Комплект сохраняет ограничения исходного MEKF, перечисленные в [разборе фильтра](QAV250_EKF_review.md). Успешная компиляция не подтверждает точность ориентации на реальном коптере.
