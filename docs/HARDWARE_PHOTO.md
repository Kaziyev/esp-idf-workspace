# Макетная плата пользователя · 20 сентября 2026

Направление «вперёд» выбрано пользователем: **к USB-разъёму ESP32, вверх на фотографии**. Чёрный модуль BMI270 расположен справа внизу, фиолетовый BMM150 — над ним. Ниже — номинальная ориентация по видимым стрелкам на платах; точность шелкографии и небольшие углы установки требуют проверки измерениями.

## Системы осей

| Положительная ось | BMI270 (чёрный) | BMM150 (фиолетовый) | Корпус / модель |
|---|---|---|---|
| X | Влево на фото | Вправо на фото | Вверх на фото, к USB |
| Y | Вниз на фото | Вниз на фото | Влево на фото |
| Z | Из плоскости к наблюдателю | В плоскость от наблюдателя | Из плоскости к наблюдателю |

Знаки Z выведены из видимых направлений X/Y и правой системы координат. Это вывод по фото, а не измерение датчиков. Принцип согласования осей и проверка правой системы описаны у [Bosch, Axes remapping, разделы 2–3](https://www.bosch-sensortec.com/media/boschsensortec/downloads/application_notes_1/bst-mhs-an001.pdf).

```text
BMM150 -> BMI270:     m_IMU = [-mx_BMM, +my_BMM, -mz_BMM]
BMI270 -> корпус:     v_body = [-vy_IMU, +vx_IMU, +vz_IMU]
```

Оба преобразования — вращения с det = +1. Нельзя поменять только знак X магнитометра: это создаст отражение и нарушит согласованность правых систем. Акселерометр и гироскоп используют одну собственную систему BMI270.

Первое преобразование выполняется **до оценки ориентации**. Второе переводит готовую ориентацию и все векторы в оси корпуса. Кватернион и матрица учитывают смену базиса, а не простую перестановку Roll/Pitch.

## Панель и существующая прошивка

При отсутствии сохранённой настройки панель включает профиль **«По фото · вперёд к USB»**. Ранее сохранённая точная двухпозиционная калибровка имеет приоритет. Чтобы заменить её начальным профилем, нажмите **«Монтаж как на фото · вперёд к USB»**.

Для старого raw-потока `ax…mz` оставьте **«MAG без отметки осей → Как на фото: BMM150 → IMU»**. Браузер переведёт MAG в оси BMI270 перед AHRS. Если в собственной старой прошивке MAG уже был совмещён с BMI270, выберите «Уже в осях IMU».

Новая прошивка указывает `"mag_frame":"bmi270"`; браузер доверяет этой отметке и не выполняет повторный поворот. `"mag_frame":"bmm150"` означает собственные оси магнитометра и требует преобразования по фото. Неизвестная отметка отключает MAG, сохраняя доступные ACC/GYRO/q.

Если старый поток уже содержит **q/RPY из MEKF**, браузер не может исправить прошлые магнитные коррекции фильтра изменением его выходного кватерниона. Панель выводит предупреждение; для этого режима нужна обновлённая прошивка. В raw-режиме браузер рассчитывает ориентацию заново и перепрошивка для применения номинального профиля не обязательна.

## Прошивка

В `idf.py menuconfig → QAV250 → BMM150 axes relative to BMI270` по умолчанию включён профиль `Photo breadboard`, `CONFIG_QAV250_MAG_AXES_PHOTO=y`. Вариант `Identity` предназначен только для физически совмещённых осей модулей.

В `read_bmm150()` сначала выполняется компенсация Bosch, затем существующая коррекция MAG_OFFSET/MAG_SCALE в осях BMM150, затем преобразование `(-X,+Y,-Z)`. Результат используется при начальном усреднении MAG, инициализации MEKF, каждой магнитной коррекции и в обоих вариантах JSON. Поэтому q MEKF и переданный MAG относятся к одной системе BMI270. Точные hard/soft-iron параметры по фотографии определить нельзя; текущие значения остаются заглушками.

Соберите и прошейте по [README](../README.md#сборка-и-прошивка-esp32-s3). Автоматического доступа к COM-порту или прошивки платы при внесении этих изменений не выполнялось.

## Перекос около 10°

Профиль по фото задаёт номинальные оси, **не точный монтажный угол**. Для компенсации наклона BMI270 относительно корпуса:

1. Удерживайте макетную плату горизонтально минимум секунду; нажмите «1. Плата лежит ровно».
2. Опустите сторону USB вниз на 15–60° без бокового крена, удерживайте минимум секунду; нажмите «2. Передняя сторона вниз».

После этого установочный перекос BMI270 учитывается для всех показаний корпуса. Отдельный перекос BMM150 относительно BMI270 эта процедура не измеряет: номинальное совмещение MAG задаётся стрелками, а для точного курса оба модуля должны быть закреплены без взаимного перекоса либо нужно отдельно измерить их относительное вращение. Не следует произвольно прибавлять или вычитать 10° из Euler-углов.

## Подключение

По фотографии не удаётся надёжно проследить все провода до GPIO ESP32. Сохранены настройки работающего проекта: SDA = GPIO40, SCL = GPIO39, I²C = 100 кГц. Это настройки кода, а не подтверждение проводки на снимке. Номера GPIO можно изменить через menuconfig, если фактическое подключение другое.

## Проверка

На горизонтальной макетной плате после точной калибровки ACC корпуса должен быть около `[0, 0, +1] g`. При опускании стороны USB — Pitch положительный, `ACC X < 0`; при опускании правой стороны — Roll положительный. Поворот носа влево даёт положительный Yaw. Вдали от магнитных помех направление `R · MAG_body` должно оставаться примерно постоянным при наклонах платы; систематическое движение этого вектора указывает на несогласованные оси/монтаж или магнитную калибровку.

Программные проверки: `node tests/telemetry.cjs`. Проверка используемой в прошивке C-функции:

```powershell
New-Item -ItemType Directory -Path build-tests -Force
gcc -std=c11 -Wall -Wextra -Werror tests/sensor_axes.c -o build-tests/sensor_axes.exe
.\build-tests\sensor_axes.exe
```

Они проверяют знаки, правую систему, сохранение нормы, старый raw-поток, новый q-поток и отсутствие двойного преобразования. Они не подтверждают фактические GPIO, маркировку breakout-модулей или точность курса на реальной плате.
